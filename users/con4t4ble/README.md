# con4t4ble keymap

https://kbigwheel.hateblo.jp/entry/no-pain-with-japanese-input

こちらでまとめた通り、プログラミング中のタイピングと日本語入力のタイピングをどちらも快適にするというコンセプトで作ったキー入力上の機能の詰め合わせ。

以下がその機能。

1. auto disable ime - ';' や ':' のような全角での入力頻度が低いキーを押したとき、自動で日本語入力を OFF にする機能(言い換えると一律半角で入力する機能)。日本語入力 ON のまま記号を入力したときのイラつきを解決する
2. auto disable ime timer - しばらくキー入力がなかったとき、自動で日本語入力を OFF にする機能。多くの場合、日本語入力をしている時間のほうが短いのでデフォルト日本語入力 OFF にできる
3. mimic keymap - OS 側のキーボード認識が US と JIS のどちらであっても、キーボード側は US キーボードとして記号を入力する機能。同様に OS 側の状態に関わらず JIS キーボードとして記号を入力することもできる - OS 側の状態へなるべく依存せず、一貫したキー入力を実現したくて実装した機能。

## 使ってみてわかった問題点

### users/con4t4ble の機能自体の問題点

#### 複雑性の高い auto disable ime

auto disable ime 機能はやってみると結構全角で記号を入力したいパターンがあることがわかった。
例えば「」などはよく全角で入力する。半角の方の[]もよく使うため、この使い分けのために KC_DISPEL を使っているが、かなり複雑性が高い。なれた今でもしばらく使わなかっただけで場所ややり方を忘れるし、同時入力 4 キーなどへ頻繁になるため入力難易度も高い。

#### mimic keymap では一部のショートカットキー入力ができない

具体的には vscode で求められた Ctrl-Shift-0。OS 側が JIS、キーボード側が US 入力の場合、Ctrl-Shift-0 と押したときは mimic 機能により実際には Ctrl-Shift-9 扱いになる。これは、JIS と US の記号入力の差分を吸収するために Shift を押した状態で 0 を押すと 9 へすり替える設定になっているため。通常の文字列入力では問題ないが、vscode のように入力したキーそのものをショートカットキーとして使う = 押したキーそのものを物理的に認識する場合は問題になる。

#### 日本語入力 OFF でなんらかの処理をしていると auto disable ime timer で暴発する

具体的には windows + google 日本語入力で発生。google 日本語入力はデフォルトで?入力中に無変換ボタンを押すと入力中の文字列がキャンセルされてしまう。これは日本語入力中にしばらく考えていると timer が働いて入力中の文字列が消える現象を引き起こしてしまう。

### 本質的ではない、または派生的な問題点

#### MAC と P の両方で簡単に切り替えられるようにしているがそうめったに切り替えない上その機能のためのコストが高い

書いているキーマップのすべてで Default Layer を利用した PC/Mac の同時サポートを行っているが、そのためのコストがかなり高い。キーマップが 1 枚増えることもだが、disable_ime などデフォルトレイヤーを読みに行って対応した日本語入力 ON/OFF ボタン(つまり無変換 or 英数)を押すなどコードが複雑化する要因になっている。

#### 特定キーボード用の combo キーが混入している

config_macro.c に halberd 用のコンボキー設定が入ってしまっている。これはもともとこの users/con4t4ble が halberd キーマップ定義から持ってきたため。halberd 下へ移動したほうがよいが、長いこと使い続けており今更変更すると意図しないところまで影響が出そうなため、v2 を作ることにしてこちらは変更していない。
